# Configuration: work/build_character.json

`prepare.sh` generates this file: head settings come from the head profile, body settings come from measurements (`work/measure/measure.json` records the raw data behind each value), and the rest use defaults from two delivered outfits. You can edit it manually after generation; rerunning `prepare.sh` requires `--force`, which renames and retains the old file but does not read its manual values. Put values that must persist in `work/build_overrides.json`.

Coordinates are in meters, with Z up and -Y facing the model's front. When `frame` is set, all head-related positions use head profile coordinates (`x_profile = (x - t) / s`); body values are also measured in this coordinate system.

## Basics

| Key | Meaning |
|---|---|
| `kit` | Charakuru kit root directory |
| `rig`, `collection` | Armature and collection names in the weighted result (`CharaKit_Weights_<id>_Rig`) |
| `assembly_blend` | Kit assembly result, used to retrieve hair |
| `frame` | Scale and translation into head profile coordinates; see Head Profiles |
| `hair_affine` | New heads: this project's own assembly transform; hair is placed with it before conversion to profile coordinates |
| `keep_meshes` | Meshes to retain besides Body and Head (skirt, ribbons, drawstrings, etc.) |
| `output_blend`, `spring_config_out`, `report_out` | Outputs |

## Head and Face

| Key | Meaning |
|---|---|
| `head_affine` | Transform from assembly space to final position, fitted from head vertices in the weighted result |
| `head_texture`, `hair_texture`, `hair_texture_clean` | Head profile textures |
| `skull` | Closed skull: center, fitting range, nape, eye socket clearance |
| `neck_loft` | Neck transition: neck axis, starting height, flare amount |
| `jaw_round`, `crease` | Jaw rounding, creases |
| `hair_cavity_box` | Region for removing hair fragments near the mouth and nose |
| `eye_white_fill` | Sclera repainting |
| `brow_overlay`, `face_fx` | Brow overlay, anime decals |
| `earring` | Earrings: position range and physics parameters |
| `iris_layer` | Heads with irises painted on eyeballs: split into an iris layer (one `EyeIris_R/L` material per eye) and an eyelid layer; gaze translates the iris texture |
| `mouth_open` | Maximum opening height for “ah,” as a mouth-width multiplier (start at 0.6 times for realistic faces, about 1.1 times for anime). Only reduces `aa/ih/ou/ee/oh/happy_mouth/surprised_mouth`; when unset, new heads may still be reduced through `MOUTH_GAIN` |
| `mouth_mood` | Natural amplitude limits for angry and sad mouth shapes: `width`, `open`, `arc`, `rise`, `drop` (relative to mouth width), and `angry_frown`; `false` disables |

## Hands and Body

| Key | Meaning |
|---|---|
| `template_hand` | Fitted template hand and cut position (generated by `polish/hand/`) |
| `finger_clean` | Starting point for finger-weight cleanup |
| `helper_bones` | Wrist helper bones. `mode: band`: one wrist helper bone (long sleeves); `mode: twist`: divide the forearm into `count` twist segments, starting at forearm `start` (used automatically for exposed forearms) |
| `crotch_blend` | Crotch weights: centerline, crotch bottom, hip-joint height, half-width, and minimum pelvis proportion `pelvis_min` |
| `hand_skin` | Unify hand and neck skin tones (neck handled by `region_paint` for outfit changes) |
| `waist_blend` | Torso weight proportions shared by waist layers |
| `cuff_lining` | Cuff-lining repainting and deletion; enable only when template hands replace original hands. When retaining original hands, remove or set to `false`, or hands sharing the material and color will be deleted by mistake |
| `region_paint` | Recolor by mesh piece: `cloth` (remove skin colors from clothing pieces), `band` (uniform-color bands such as belts), `underside` (downward-facing faces of specified pieces), `skin` (unify skin-piece tones), `metal` (color small accessories). Select a piece as “the piece containing the face nearest a given point.” `cloth` also handles faces invisible from all four directions (`lift_hidden`) and adjacent pieces with the same material and color (`siblings`) |

## Automatic Measurement Rules

| Key | Measurement method |
|---|---|
| `frame` | Same head: fit head vertices point by point to the profile's `head_rest.npy`; new head: fit eye corners, mouth corners, mouth center, nose tip, and chin to the corresponding profile landmarks |
| `neck_loft.axis`, `z_flare`, `z_neck` | Flare starts 2 mm above the head's lowest point; the straight section starts 2 mm below the front neckline (no higher than 3 cm below the flare); the axis is the center of the neck cross-section at that height |
| `hair_colliders` (body portion) | Neck, upper-chest, and shoulder bone positions plus fixed offsets, scaled by shoulder spacing |
| `finger_clean.x_min` | 5 mm outward from the outermost base joint of the four fingers |
| `waist_blend.z` | From 3 cm above the hip bone to 3.5 cm above the spine bone |
| `cuff_lining` | Enabled for long sleeves with a sleeve material when template hands have replaced original hands; starts 6 cm inward from the elbow, deletion starts 7.5 cm inward from the wrist |
| `helper_bones` | `twist` for exposed forearms (short sleeves), otherwise `band` |
| `crotch_blend` | Enabled when there are more than 20 centerline vertices between the legs below the hip joints (pants, shorts) |
| `skirt`, `ribbon` | Springs (hair and skirt physics) in the kit's classification; motion starts downward from the top: skirts and drawstrings 15%, bows 35% |
| `region_paint` | Sample pieces at the neck, chest, abdomen, back, hips, thighs, calves, upper arms, and forearms: neck pieces are automatically treated as skin; large cool-colored clothing pieces with few warm-colored faces automatically have skin colors removed; a dark ring at the top of clothing (belt) automatically gets `band`; inspect the piece sheet and specify the rest with `--skin` and `--cloth`, using `--metal` for small items such as necklaces |

Color alone cannot distinguish skin pieces from pink or beige clothing (the pink bow at the front waist of the purple version (紫色版) is 82% skin-colored, while the denim outfit's exposed waist is only 49%), so all skin pieces except the neck require visual selection.

## Physics

| Key | Meaning |
|---|---|
| `hair` | Hair chains: root height, azimuth, bone count, separate front-hair settings |
| `skirt` | Skirt chains (omit if there is no skirt) |
| `ribbon` | Ribbons and drawstrings: mesh name, bone-name prefix, parent bone, root height |
| `hair_colliders` | Hair collision spheres: head, neck, upper chest, shoulders |

The repository does not include full project configurations for the purple version or the denim outfit. Generate this character's configuration with `prepare.sh`, then adjust using its measurements; do not copy another character's absolute coordinates.

## Preserving Manual Configuration

- **Symptom**: mouth, neck, sleeves, or skin tones revert to defaults after `prepare.sh --force`.
- **Cause**: the generator reads `profile.json`, `measure.json`, command-line arguments, and the override file; it does not merge the old `build_character.json`. `mouth_open` and `mouth_mood` are not in the head profile copy allowlist; `iris_layer` is created by the new-head branch and lacks full same-head profile round-trip support.
- **Action**: save manual values in the project's `work/build_overrides.json`. Each configuration generation merges nested objects by key; ordinary array keys and scalars replace entire values, while array keys suffixed with `+` append to the generated list, for example `"region_paint": {"cloth+": [...]}`. `false` applies only to options explicitly supporting disablement in code; it is not general deletion syntax.
- **Configuration key**: `work/build_overrides.json`; Character 2 (人物2) can use the complete example below.

```json
{
  "mouth_open": 0.6,
  "neck_widen": {"factor": 1.1}
}
```

`neck_widen.factor` is equivalent to `prepare.sh --neck-widen 1.1`, meaning 1.1 times the width. It is a merge exception: the generator reads factor first, then recalculates `z_from/ramp` from measurements rather than merging those two fields from the override file; an explicitly non-1.0 command-line `--neck-widen` takes precedence. Output paths `output_blend/spring_config_out/report_out` and `generated` are also written last by the generator and are not preserved from the override file.

The purple version preserves `arm_joints`, `cuff_follow`, `skirt_leg_follow`, `sleeve_fit`, `hand_skin`, and `safety_shorts` through the override file. These values depend on the character's measurements; no universal absolute coordinates are provided.

## Selecting Additional Configuration by Symptom

| Symptom | Cause | Action | Configuration keys and units |
|---|---|---|---|
| Neck too thin | Generated proportions differ from the reference | Gradually widen above the transition start | `neck_widen.factor` multiplier; `z_from` start m, `ramp` transition length m |
| Sleeves enter the body when arms lower | Bone joints are offset from sleeve centers | Move joints while keeping bone chains connected | `arm_joints`: specify `[y,z,optional x]` for `shoulder/upper_arm/lower_arm/hand`, in m; x takes the sign for each side and is retained if omitted |
| Cuffs clip through hands during wrist rotation | Cuffs follow only the forearm | Assign some hand weight to cuffs | `cuff_follow.back/front/full_at`: distances from the wrist joint along the forearm axis in m; back points toward the elbow, front toward the hand, full_at is where maximum weight is reached; `max` weight proportion |
| Skirt does not follow legs; close-fitting areas clip | Spring weights differ from body motion | Add leg weights to the skirt by height and azimuth | `skirt_leg_follow.z_full/z_top` full/zero-weight heights m; optional `z_off/z_zero` heights m for fading to zero below; `angle/width` azimuth center/range °; `max` weight proportion |
| Clipping at close-fitting skirt waist and hips | Skirt and body weights differ | Transfer weights from the nearest body surface | `skirt_contact.materials` list of body material names; `z_max` face-selection height m; `full/none` full/zero-influence distances m |
| Puff sleeves clip through torso when lowered | T-pose sleeve shape does not suit lowered arms | Fit across multiple poses, preserving shoulder and cuff seams; decorations follow the sleeve surface | `sleeve_fit`; fields below |
| Skin-colored lining visible in other clothing areas | Projection color contamination | Recolor or delete specified regions; exclude hands when retaining original hands | `lining_regions[]`, same fields as `cuff_lining` |
| No safety shorts under skirt | Texture lacks them | Paint in `polish.sh` after expressions and before joint corrections, changing only the texture | `safety_shorts.hem` hip-to-knee proportion, default 0.26; `material` default `Material_lower_body`; `palette` default `lavender`, also supports `cream` |
| Opening a face shell's mouth exposes board edges | Shallow backing cannot cover side views | Generate a closed mouth bag by default; whole heads use the existing pocket | `mouth_bag`; `false` only reverts face shells to the old backing |

Safety shorts example: `"safety_shorts": {"hem": 0.5, "material": "Material_lower_body", "palette": "lavender"}`. `hem: 0.5` means 50% of the way from hip to knee, not 0.5 m.

### Sleeve Fitting Fields

| Field | Meaning |
|---|---|
| `targets` | List of region names involved in avoidance, such as `torso`, `waist`, `skirt`; must match this model's regions |
| `passes`, `smooth` | Fitting passes and smoothing iterations per pass |
| `poses` | List of `[down,swing,flex]` arrays: arm lowering, forward/backward swing, and elbow flexion angles, in ° |
| `seam_rings` | Number of fixed adjacency rings at shoulders and cuffs |
| `deco_max_verts` | Separate decorations below this vertex count follow the sleeve surface as a whole |
| `reach`, `max` | Surface query distance and maximum displacement, in m |
| `gap` | Gap by target region name, in m |
| `min_radius_frac` | Compressed radius from the arm axis must remain at least this fraction of the original radius |

### Mouth Fields

| Key | Default and meaning |
|---|---|
| `mouth_mood.width` | 1.0 times closed-mouth width; limits angry and sad mouth width |
| `mouth_mood.open` | 0.03 mouth widths, maximum lip-gap opening |
| `mouth_mood.arc` | 0.10 mouth widths, maximum mouth curvature |
| `mouth_mood.rise` | 0.04 mouth widths, maximum rise at the upper-lip center |
| `mouth_mood.drop` | 0.06 mouth widths, maximum downward mouth-corner movement |
| `mouth_mood.angry_frown` | 0.8 times sad deformation, replacing excessive teeth-baring anger |
| `mouth_mood: false` | Disable the natural amplitude limits above |
| `mouth_bag.rim_x/rim_z` | 1.35 / 0.9 half-mouth widths, horizontal/vertical radii of the bag opening |
| `mouth_bag.behind` | 0.003 m, or 3 mm behind the skin |
| `mouth_bag.depth` | 1.1 mouth widths, inward depth |
| `mouth_bag.rings/around` | 8 rings, 48 points per ring |
| `mouth_bag.low_band` | 0.6 half-mouth widths, vertical blend-band width for the bag wall following the lower lip |

The `mouth_open` scale factor is capped at 1.0 and never enlarges existing mouth shapes. Mouth width is also limited by visible mouth corners; the Director Console uses `extras.vrmPolish.mouthWidth` and `mouthNarrow` to retract excess width in combined mouth shapes. Character 2's mouth width/interpupillary distance is 0.52 at rest and 0.61 smiling; the reference is about 0.76 at rest, with a preferred smile range of 0.55–0.62. These do not replace aesthetic acceptance for this character.

## Field Index for Existing Modules

The fields below are actually read by the build. Unless otherwise noted, coordinates, radii, and distances use m in profile coordinates; angles use °, while weights, colors, and gains are dimensionless. Texture smoothing scales use pixels; mesh ring counts, neighbor counts, and sample counts use integers. Fields passed through to modules are defined by the corresponding `polish/face/` implementation; a module name is not a complete parameter specification.

| Configuration block | Fields and functions |
|---|---|
| `crease_pairs` | Path to crease vertex-pair JSON; the main build reads it unconditionally, and new heads generate their own file |
| `crease` | `components` component JSON path, `pieces` left/right crease component IDs |
| `jaw_round`, `brow_overlay` | `module` module path; remaining settings pass to the jaw/brow overlay module; new heads remove inapplicable items according to structure |
| `face_fx` | `module`, `dir`, `hair_object`, `effects`, `warp`: module, decal directory, hair object, effect definitions, landmark-based transform. The expression stage supports omission, generating no decals when absent; do not casually delete this block from the starter head profile template, as generator initialization still reads it |
| `iris_layer` | `eyes` eyeball vertex lists for each side, `rims` eye socket vertices; generated by new-head identification; painted irises use UV gaze, separate irises still move geometrically |
| `skull` | `center` center; `fit_mask_z` face-fitting sampling start height m, `fit_hair` hair-fitting toggle, `fit_hair_inset` inset m, `fit_ry_ratio` depth/width ratio; `segments/rings` subdivisions; `inside_face/under_hair/blend/smooth/r_min` inset, under-hair gap, blending, smoothing, and minimum radius; `hair_sample_z/hair_shade/skin_sample_box/skin_tone` color sampling; `nape` nape color-gradient height range m |
| `skull.nape_fit` | `ear` ear exclusion range (`feather/x_min/y/z_min`, in m); `out` expansion m, `y/z` gradient ranges m |
| `skull.eye_clear` | `ignore_iris/max/x/z`: ignore-iris flag, eye socket clearance limit and range |
| `skull.mouth_pocket` | `depth/rx/rz/x/y_front/z`: skull mouth recess depth, radii, and position; distinct from the expression stage's `mouth_bag` |
| `eye_white_fill` | `components/boundaries` data paths; `iris/sclera/skin/openings/near_iris/iris_main` component and opening selections; `bin/fill/relax/iris_soften/out` sampling, repainting, smoothing, iris softening, and output |
| `eye_white_fill.lid_fill` | `lash/z/absx/relax`: eyelash components, range, and repaint smoothing |
| `hair_cavity_box` | `x/half_x/z/y_min/y_max/hard/parity`: front-of-face hair-fragment selection, hard deletion, and parity test |
| `neck_loft` | `axis/z_flare/z_neck` axis and heights; `around/along` circumferential/longitudinal sample counts; `lift/flare_front/flare_side/flare_back/max_rise/sink` lift, flare, maximum rise, and inset; `ring_smooth/color_smooth` contour/color smoothing; `tone` color-sampling method; `rows_neck/rows_flare` section sampling; `ext/ext_offset/top_offset/ext_jump` extension positions and offsets; `cover_stump/cover_smooth_rows/cover_keep_above_closed/stump_material/stump_band` original neck-stump coverage, smoothing, closed-section retention, material, and range |

| `hand_skin` | `material/neck_material/neck/tone_from` materials, whether to process the neck, color source; `reach/arms/arm_radius` sampling range and arm settings; `skin_all/skin_all_max_abs_x/skin_dark_box/skin_dark_min_mean/neck_flood` all-skin and dark-region selections, brightness threshold, and neck expansion; `sigma/broad/detail` texture smoothing and detail strength |
| `finger_clean` | `x_min` cleanup start m, `dominant/min_bleed` own-finger dominant-weight and cross-finger weight thresholds |

| `hair` | `z_root/root/blend/angles/bones/physics`: root height, rooting method, transition m, azimuth °, bone count, spring parameters; `front` front-hair settings, `front_fade` fade angle range °, `front_fade_min` minimum influence proportion; `length_physics.ref` reference length m; `hidden_max_y/scalp_pin` hidden region and scalp pinning range |

| `earring` | `x/y/z/max_size/max_verts/parent/physics`: position selection m, maximum size m, maximum vertex count, parent bone, physics parameters |

The generator may still write `neck_loft.flare_power`, but the main build does not read it; changing it has no effect. `generated` is only a generation record, not a behavior parameter.

## Pipeline Files and Environment

| Input | Purpose |
|---|---|
| `work/skirt-colliders.json` | Plan from the kit's `scripts/plan-skirt-colliders.py`; when present, `build.sh` calls the kit's `apply-skirt-colliders.py` to apply it |
| `work/skirt-extra-colliders.json` | When present, `polish/post/add_skirt_colliders.py` then adds arm and hand collisions |
| `KIT` | Charakuru root directory, inferred from the project directory if unset |
| `BLENDER` | Blender executable, defaulting to the macOS application path; changing the path does not imply support for other platforms |
| `APP_URL` | Request registration address, default `http://localhost:8780` |

`prepare.sh` arguments include `--skin`, `--cloth` (piece sheet IDs), `--metal`, `--neck-widen`, and `--force`. Python 3 + numpy + Pillow are required; the polishing entry points require macOS and zsh, and kit scripts additionally require Node.js 22 and Blender 5.2 + VRM Add-on. Entry points enable `set -e` + `pipefail`, but error-tolerance wrapper exceptions remain; see [Charakuru Integration](charakuru-integration.md).
