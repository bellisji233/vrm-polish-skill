# 头部档案

表情和头部修整依赖头部网格本身：五官在哪个位置、哪些顶点是眼白和虹膜、贴片贴在哪里。这些数据按「头」保存，叫头部档案。

## 起步档案

新用户直接使用 `assets/head-profile/`：只有标定点、头部设置和二次元贴片，不含第一个角色的网格、脸部贴图和头发贴图，也没有 `head_rest.npy`。任何新的头都可以从它进入自动识别流程，支持的结构见下文「新的头」。

```sh
zsh polish/pipeline/prepare.sh <项目> assets/head-profile
zsh polish/pipeline/polish.sh <项目> assets/head-profile <输出.vrm>
```

人物2 已从头验收。用起步档案生成的配置和用完整档案逐项相同，表情阶段完整跑通。完整档案只在同一个头换衣服、需要逐顶点复用时使用。

## 完整档案里有什么

一个头部档案是一个文件夹：

| 内容 | 用途 |
|---|---|
| `profile.json` | 构建配置里属于头的部分（头壳、头发分链、下颌、透眉、贴片、眼白补画、耳坠等），路径相对档案文件夹；另有头部碰撞球、脸部肤色、表情相机 |
| `head_rest.npy` | 头部顶点在档案坐标里的位置，用来判断新项目是不是同一个头，并算出 `frame` |
| `expr-data/` | 部件编号（眼白、虹膜、睫毛、眉毛、嘴）、眼和嘴的开口边界、眼角嘴角等标定点 |
| `face/` | 修好的脸部贴图（去眉、嘴线减淡）、下巴折痕顶点对、组装空间变换 |
| `hair/` | 头发贴图和清理后的头发贴图 |
| `fx/` | 脸红、星星眼、爱心眼、猫嘴等贴片和 `fx.json` |

从做好的紫色头类项目打包。`make_profile.py` 目前要求独立眼睛、眉毛、折痕部件；人物2 类会报错说明缺少哪些配置，不支持打包。`roles.json`、`overrides.json` 存在时一起复制：

```
blender -b <项目>/work/weights/weighted.blend --python polish/profile/make_profile.py -- <项目>/work/build_character.json <档案文件夹>
```

## 同一个头换衣服

复用原候选或原头部 GLB，才能保留同一个网格。用相同图片重新生成，不保证顶点对应。

1. `prepare.sh` 把新项目的头部顶点和 `head_rest.npy` 逐点拟合，得到缩放 `s` 和位移 `t`（顶点数不同或均方根拟合误差不满足 `rms < 0.002 × s` m 时判为不是同一个头）。
2. 写进新项目配置的 `frame: {"s": s, "t": [tx, ty, tz]}`。
3. 构建和表情在档案的坐标里运行，结束后换回，档案的数据和数值原样可用。

牛仔装上自动拟合的结果和手算一致（s = 1.03604，t 相差不到 0.01 mm）。

牛仔装用这个办法复用了紫色版的全部头部修整和 约 100 个 VRM 表情（标准表情、ARKit 52、视线、二次元贴片、6 个关节修正），脚本一行没改。

## 新的头

新的头不需要先手工建档案。`prepare.sh` 发现顶点数或形状和档案的头对不上时，自动走新头路线：

1. **识别部件**（`polish/face/locate.py`）：把头部网格按连通部件分开，用部件之间的关系判断角色：
   - 脸部皮肤：开口最多的大部件；
   - 眼睛开口：皮肤上左右对称的两个洞；
   - 眼白：开口里最大的浅色部件；
   - 上睫毛：开口上方的深色大部件；
   - 虹膜：眼白前面的部件；
   - 眉毛：上睫毛上方左右对称的宽部件；双眼皮线：睫毛和眉毛之间的细部件；
   - 小部件：贴着开口边缘的是下睫毛，扁平、深色、贴上缘的是眼线，扁平且在虹膜范围内的是虹膜高光；
   - 鼻子、耳坠；
   - 嘴线：脸下部中间比肤色暗的贴图；
   - 下巴、鼻尖。

   紫色版头部的 59 个部件全部和手工标定一致，眼角四点误差 0 mm。
2. **对齐到档案的脸**：用眼角、嘴角、嘴中心、鼻尖、下巴 9 个点，拟合一个统一缩放加位移，写进 `frame`。头部设置在这个坐标里适配。眼白、虹膜层、头壳、下颌、透眉按新头结构重建或跳过；嘴部按本头标定换算，不是原样照搬全部参数。
3. **这个头自己的数据**写到 `work/measure/`：
   - 部件列表和编号（眼白补画、双眼皮、透眉用）；
   - 下巴折痕（档案折痕线附近的凸折边）；
   - 自己的组装变换（放头发用，`hair_affine`）；
   - 修好的脸部贴图（`polish/face/head_texture.py`：去掉画在皮肤上的眉毛、脸颊折痕和下颌的轮廓线，嘴线调成柔和的唇色），前后对比图在 `work/measure/texture/贴图修整前后.jpg`。
4. **表情**：表情工作区里再识别一次部件（这时已有头壳和脖子过渡），表情脚本按识别出的编号运行。

用牛仔装当作新头完整跑过一遍（不用逐顶点对应，只用上面的识别和对齐）：

- **对齐**：缩放 1.03605，逐顶点精确拟合是 1.03604；
- **成品**：约 100 个 VRM 表情（标准表情、ARKit 52、视线、二次元贴片、6 个关节修正）齐全，中性脸、闭眼、笑、张嘴、生气、眨眼和逐顶点版本的差异约占画面 1%。

第二个角色（人物2，男生）是真正不同的头，结构也和紫色版不同：

- 睫毛长在脸皮上，没有单独的睫毛部件；
- 虹膜画在眼球上，没有单独的虹膜部件；每只眼睛的眼球有两份重叠的拷贝；
- 眉毛只画在皮肤上；
- 头部是闭合的整颗头，不是脸部面具，所以不需要补头壳。

这类头的处理：

- 识别结果里的 `structure` 标出缺哪类部件；
- 眉毛动作改成移动额头皮肤，画上去的眉毛跟着走；
- 画在眼球上的虹膜切成独立材质层，视线平移贴图；原本有独立虹膜部件的头仍按几何移动；
- 眼白补画、透眉、头壳、下颌圆化自动跳过；
- 嘴部的位置、口腔大小、笑容幅度和嘴部动作的影响范围，都按这张脸自己的标定点（嘴角、鼻尖、下巴、瞳距）换算；
- 二次元贴片按标定点挪到这张脸上。

结果：约 100 个 VRM 表情（标准表情、ARKit 52、视线、二次元贴片、6 个关节修正），ARKit 52 绑定齐全，在导演台按 120 Hz 看过中性、闭眼、笑、生气、悲伤、惊讶、放松、五个口型、四个方向视线，以及 Reze 舞。

**限制**：

- 识别规则支持两种结构：眼白、虹膜、睫毛分开，或者画在一起；目前只在 Tripo 生成的头上验证过。都不像的头会在识别这一步报错，并说明缺哪个部件。
- 脸型和档案差别很大时，头部设置只是近似：对齐后的标定点误差记在 `measure.json`，超过几毫米要重点看下巴、口腔和脸颊。
- 新头头发以 `hair.root: head_width` 重新定根，位置由测量拟合。贴片优先用本项目 `work/fx/fx.json`，否则按标定点变换；仍需检查位置。
- 档案不保存 `mouth_open`、`mouth_mood`，`iris_layer` 也没有完整的同头档案往返支持。持久手调值放到 `work/build_overrides.json`，见[配置说明](配置说明.md)。

## 按现象选路线

| 现象 | 原因 | 处理 | 配置键 |
|---|---|---|---|
| 没有已有角色档案 | 新项目还没有逐顶点基准 | 使用 `assets/head-profile/`，自动识别本头 | 档案 `starter`、`landmarks`；生成 `frame` |
| 换衣服后头位置变化 | 同网格缩放、平移不同 | 用完整档案逐点拟合，保留原候选 | `head_rest.npy`、`frame.s/t` |
| 新头与档案结构不同 | 眼睛、眉毛可能画在贴图上 | 按 `structure` 选择几何或贴图路线 | `iris_layer`、`eye_white_fill`、`brow_overlay`、`skull` |
| 张嘴露出浅色内壁 | 输入只有脸壳或已有口袋未整理 | 统一成封闭口腔袋，见[通用问题手册](通用问题手册.md) | `mouth_bag`、`mouth_open` |

表情阶段构建 77 个形态键。最终 VRM 登记数量随角色贴片、保留项和修正项变化，不写死总数。
